# ADR 0001：SusShare 是 VPN 内的临时共享板

## Status

Accepted

## Context

SusShare 的原始定位容易滑向设备同步、P2P 传输、实时剪贴板和账号体系。实际使用场景是少数受信任设备处于同一 VPN 中，需要一个打开即用的临时内容面板：上方查看已有共享内容，下方发布文本或文件，手动刷新获取别人的新内容。

## Decision

SusShare MVP 是一个 Go 单体服务，提供 Web UI 和 REST API，只做 VPN 内的临时共享板：

- 共享条目分为文本和文件两种类型；一次多文件上传创建多个独立文件条目，不引入上传批次实体。
- 条目不携带来源设备标签，服务端不虚构设备身份。
- 保留策略只有有限时长，MVP 为 1 小时到 7 天；没有“永久”条目。
- 文本条目默认最大 1 MiB，可通过服务器配置调整。
- 页面加载和手动刷新时调用 `GET /api/v1/items`，不做 WebSocket、轮询或推送。
- 本地文件系统是唯一持久化存储，不引入 PostgreSQL、Redis 或账号体系。
- 服务级保留策略决定新条目的过期时间；条目创建时固化 `expires_at`。
- 使用登录密码作为共享基础认证，密码以 Argon2id 哈希保存。
- 修改登录密码后，所有现有 Session 全部失效，当前浏览器也必须重新登录。
- 运行时写回配置时不需要保留管理员手写注释。
- Docker 挂载 `/config` 与 `/data`，配置文件控制服务器级边界。

## Consequences

- 系统没有设备、发送、接收、同步等领域概念，交互模型保持简单。
- 其他设备发布内容后，当前页面不会自动变化，这是产品决策而非缺陷。
- 单一共享密码意味着所有登录者都具有读取、下载、发布和删除全部共享条目的权限。
- 文件系统必须同时承担内容存储和元数据存储，创建、删除、列举和 TTL 清理需要明确的原子性规则。
- 配置分为服务器静态配置和运行时可变设置，不能让 Web UI 变成完整管理后台。

## Resolved Questions

1. “永久”不属于 MVP。保留策略必须是有限时长，避免 TTL 清理、容量控制和领域语义出现特殊分支。
2. 文本使用独立上限，默认 1 MiB，不借用 `max_file_size`。
3. 浏览器原生能力可用于安全类型的预览；不安全或未知类型走下载。详见 ADR 0003。
4. 条目不展示来源设备。
5. 修改密码后所有 Session 失效，包括当前浏览器。
6. 配置文件重写后不保证保留管理员手写注释。

## Alternatives Considered

- 设备自动发现和实时同步：复杂度高，且当前场景不需要。
- 数据库存储元数据：对单实例、低并发、TTL 清理的共享板过度设计。
- 每个条目单独设置 TTL：会增加发布表单和 API 语义，MVP 先使用服务级默认值。
