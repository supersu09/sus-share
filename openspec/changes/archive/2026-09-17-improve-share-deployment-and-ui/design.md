## Context

当前服务在 `cmd/sus-share/main.go` 直接把 API 和静态文件挂到根路径；`internal/web/static` 中的资源与 API URL 也全部以 `/` 开头。认证配置要求启用认证时必须提供 Argon2id 哈希，`internal/auth` 还强制密码长度为 8 到 1024。UI 是原生 HTML/CSS/JS，发布文本后没有把响应中的新条目写回列表。

## Goals / Non-Goals

**Goals:**

- 保持根路径部署不变，同时支持 `/share/` 这类外部前缀。
- 让默认部署可以不用先生成哈希，直接用 `password` 登录。
- 不破坏已有自定义密码哈希。
- 用创建响应驱动列表更新，避免发布后再发一次列表请求。
- 使用编译期 TailwindCSS 产物，运行时不依赖外部 CDN。

**Non-Goals:**

- 不新增账号体系、密码复杂度策略或密码重置流程。
- 不改变 REST API 的内部路径、请求格式和响应结构。
- 不把 API 错误消息改成中文；API 面向程序，UI 负责给人看中文。
- 不做 Nginx 自动配置或自动探测外部前缀。

## Decisions

### 1. 配置外部前缀，并在入口统一剥离

在 `server.base_path` 中配置对外前缀。配置解析时将其规范化为空字符串或 `/share` 这种形式；禁止多个斜杠、反斜杠和完整 URL。

在进程入口包一个路由适配层：

1. `base_path` 为空时原样分发。
2. 请求等于 `/share` 时重定向到 `/share/`。
3. 请求以 `/share/` 开头时先剥离该前缀，再交给现有 API 和静态文件 handler。
4. 代理已经剥离前缀时，请求以 `/` 开头，直接分发。

这样 Nginx 的两种常见配置都能工作：`proxy_pass http://service/share/;` 保留前缀，或 `proxy_pass http://service/;` 剥离前缀。现有 API handler 不需要知道前缀。

备选方案是让每个 handler 自己拼前缀。那会把一个部署问题撒到所有路由，拒绝。

### 2. 前端使用相对 URL

HTML 引用 `style.css` 和 `app.js`，JavaScript 通过一个基础 URL helper 拼 `api/v1/...`、预览和下载地址。页面只在外部前缀目录下服务，因此这些相对地址会解析到 `/share/...`；根路径部署则解析到 `/...`。

登录和登出 Cookie 的 `Path` 使用规范化后的外部前缀，根路径为 `/`。`HttpOnly`、`SameSite=Strict` 和现有 `Secure` 判断保持不变。

### 3. 密码策略移除，默认值只填补空哈希

删除认证层的最小和最大长度校验，HTML 同步移除 `required` 与 `minlength`。Argon2id 可以安全处理空字符串和短字符串，复杂度检查本来就不存在。

认证包提供一个有效哈希选择函数：

- 配置哈希非空时使用配置哈希。
- 配置哈希为空时使用内置的 `password` Argon2id 哈希。

登录验证当前密码和修改密码验证旧密码都走这个选择函数。修改密码成功后仍持久化新 Argon2id 哈希并清空 Session；空密码会生成非空哈希，因此不会重新触发默认密码 fallback。

这比在配置里隐式写入默认哈希干净：文件表示管理员设置，空值表示未设置，认证层负责有效凭据。

### 4. 用创建响应更新列表

文本发布 API 已经返回新建条目，文件上传响应也包含每个成功条目。前端成功后直接把这些元数据插入状态并重新渲染：

- 文本：清空输入，插入响应条目。
- 文件：清空 `FileList`、拖拽状态和附件信息区域，插入所有成功条目。
- 部分失败：保留失败文件的中文错误，成功条目仍进入列表。

这样不需要发布后立刻再请求列表，也避免“创建成功但列表刷新失败”让用户误以为丢内容。

### 5. TailwindCSS 编译产物进仓库

添加最小的 pnpm/TailwindCSS 构建入口，源码使用工具类和 `#66CCFF` 主题变量，生成的 CSS 提交到嵌入式静态资源目录。Go 二进制继续只嵌入最终 CSS；Docker 构建和运行时不需要 Node。

拒绝 Tailwind CDN：它让页面依赖外部网络，和内网共享板的定位冲突。

界面布局使用应用级 `100dvh` 网格：头部固定、条目列表独立滚动、底部 composer 固定且不参与页面滚动。移动端继续保持按钮和文本不重叠。

## Risks / Trade-offs

- [默认密码是刻意弱化] -> 仅在未配置哈希时生效；文档必须明确提示修改密码，已有哈希优先。
- [允许空密码会降低安全强度] -> 这是明确需求；认证和哈希逻辑仍保持 Argon2id 与 Session 失效语义。
- [子路径路由要同时支持保留和剥离前缀] -> 入口适配层用单一前缀判断覆盖两种代理方式，并用根路径回归测试防退化。
- [引入 Tailwind 构建链] -> 只在开发/样式更新时需要 pnpm，提交生成产物让运行时和 Docker 保持 Go-only。
- [前端直接插入响应元数据可能短暂缺少其他用户新条目] -> 手动刷新语义保留；本变更只保证自己刚发布的内容立即可见。

## Migration Plan

1. 部署前确认 Nginx location 与 `server.base_path` 一致；保留或剥离前缀均可。
2. 现有 `config.yaml` 不需要迁移，已有哈希继续有效。
3. 新部署可以省略 `auth.password_hash`，首登使用 `password`。
4. 如需回滚，恢复旧镜像即可；本变更不改磁盘条目格式，也不改 API 请求/响应结构。
