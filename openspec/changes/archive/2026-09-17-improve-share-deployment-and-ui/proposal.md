## Why

SusShare 目前只能稳定部署在站点根路径，Nginx 子路径代理会让静态资源和 API 请求落到错误位置；同时共享板的文案、发布后的列表刷新、附件展示和底部输入区还没有达到可直接日常使用的水准。

## What Changes

- 新增外部访问前缀配置，支持应用整体暴露在 `/share/` 这类子路径下，静态资源、API 请求和会话 Cookie 都使用正确路径。
- 登录密码不再强制长度或复杂度；未配置自定义密码哈希时，默认密码为 `password`。
- 界面文案统一为中文。
- 发布文本成功后立即刷新并显示新条目。
- 文件大小只显示在条目标题行右侧，不在时间行重复显示。
- 文件上传成功后清空附件选择和附件信息区域，不再保留逐文件结果。
- 发送内容区域固定在页面下方，条目列表在上方滚动。
- Web UI 改为 TailwindCSS 风格，主题色使用 `#66CCFF`。
- 文本发布按钮和文件上传按钮统一显示为“上传”。

## Capabilities

### New Capabilities

- `http-context-path`: 反向代理子路径部署下的资源路径、API 路径和会话 Cookie 作用域。
- `access-control`: 共享密码的默认值、密码值边界和修改行为。
- `web-ui`: 中文界面、发布后列表更新、附件状态、固定底部输入区、按钮命名和视觉主题。

### Modified Capabilities

- 无。当前主规范尚未归档建立。

## Impact

- 配置：新增外部路径前缀配置，并调整密码哈希缺省行为。
- 服务端：路由需要支持代理保留前缀和剥离前缀两种常见部署方式，Cookie Path 需要跟随外部前缀。
- Web：`index.html`、`app.js` 和样式实现将重写为基于 TailwindCSS 的界面，并统一中文文案。
- 认证：移除密码长度校验，默认密码必须在无自定义哈希时可用。
- 测试：需要覆盖子路径部署、默认密码、短密码/空密码策略、发布后列表刷新、上传后附件清理和界面布局。
